# GAME_SPEC.md — Mushak & Vinayaka: The Vahana's Journey

**Source of truth.** Any future developer or AI modifying this project reads this file
first. Do not silently rewrite the concept described here.

---

## 1. Identity

- **Title:** Mushak & Vinayaka: The Vahana's Journey
- **Genre:** 2D top-down (3/4 view) story action-adventure with story-driven character
  switching, light puzzles, action combat, a four-phase boss, collectibles and scoring.
- **Playtime:** 15–20 min first run; 20–30 min completionist.
- **Occasion:** Ganesh Chaturthi game design contest entry.
- **Delivery:** single self-contained HTML page, playable from a live link on desktop
  and mobile browsers. No accounts, no analytics, no personal data.

### Respect rules (non-negotiable)

The story begins *after* Vinayaka already has the elephant head. There is no beheading,
blood, gore, injury, mutilation, mockery, or visible harm to Vinayaka anywhere in the
game. Combat is expressed as golden divine light, rings, particles and screen flashes.
Gajamukhasura is not killed — he is resolved into mouse form and becomes the vahana.
The player's own Mushak remains a separate companion and is never replaced by him.

---

## 2. Technical deviation from the original prompt (important)

The original prompt asked for **Phaser 3 + Vite**. The build container has **no network
access**, so `npm install` is impossible and neither package can be fetched. Rather than
ship nothing, the game is built on a **purpose-written canvas-2D engine** with the same
modular decomposition the prompt asked for (§33 explicitly permits "a technically better
equivalent … but preserve modularity").

Consequences, all deliberate:

- Zero third-party runtime dependencies. Nothing to license, nothing to break.
- All art is drawn procedurally in vector canvas code (`10_art.js`). No image files.
- All audio is synthesised with WebAudio (`G.Audio`). No audio files.
- The only external asset is the opening cinematic (`assets/video/opening.mp4`).
- Final output is one HTML file, so it can be hosted anywhere or opened from disk.

If a future developer ports this to Phaser, keep the module boundaries below; the
gameplay logic in `20_entities.js` / `30_levels.js` / `50_game.js` is engine-agnostic.

```
│   ├── 40_ui.js            fonts, panels, toasts, dialogue box, HUD, touch layout, menus
│   ├── 50_game.js          state machine, chapter loading, combat resolution, scoring, screens
│   └── 60_main.js          canvas/DPR/letterbox boot, rAF loop, audio unlock, intro film
├── build/
│   ├── template.html       responsive shell, fonts, intro overlay, rotate hint
│   └── build.js            concatenates src/*.js, inlines the video as base64 → dist/
├── tests/
│   ├── smoke.js            headless full-playthrough harness (~55 checks)
│   └── bundle.js           verifies the built bundle and the published page
└── dist/
    ├── index.html          the deliverable (~4.9 MB, video inlined)
    └── game.bundle.js      concatenated source (~157 KB)
```

Files are concatenated in filename order, which is why they are numbered. Each module
declares `var G = (typeof G !== 'undefined' && G) ? G : {};` so it also loads standalone
under Node for testing; the build strips those headers inside a single IIFE.

Build: `node build/build.js` (env `MV_VIDEO`, `MV_OUT`; `--novideo` leaves the page
pointing at `assets/video/opening.mp4` instead of inlining it).

Test: `node tests/smoke.js` then `node tests/bundle.js`.

## 4. Chapters

| # | Chapter | Character | Core content |
|---|---------|-----------|--------------|
| 1 | Divine Courtyard | Mushak | movement, interact, durva/flowers/modaks, help Parvati |
| 2 | First Journey (forest path) | Mushak | blocked path, narrow crack only Mushak fits through, lever opens the way |
| 3 | Signs of the Asuras (ruins) | Mushak | footprints, dark vents, a small Asura appears → auto-switch |
| 4 | First Battle | Vinayaka | taught in order: attack, dodge, divine attack, Mushak Assist |
| 5 | Entering the Asura Realm | Vinayaka → Mushak → Vinayaka | sealed gate; Mushak runs the trap passage to the gate mechanism |
| 6 | Asura Realm | Vinayaka | small + heavy Asuras, positioning and assists, path to the arena |
| 7 | Gajamukhasura | Vinayaka | four-phase boss (§6) |
| 8 | Resolution | cutscene | Gajamukhasura resolves into mouse form and becomes the vahana |
| 9 | Return | Mushak | calm walk back, optional collectibles, no combat |
| 10 | Final Scene | cutscene | Parvati welcomes them, blessing, JOURNEY COMPLETE → score screen |

Character switching is always story-driven. There is no "choose character" menu.
Switch transition is ~1s: glow, particle burst, camera nudge, HUD change.

## 5. Controls and abilities

**Desktop:** WASD / arrows move · J basic attack · K divine attack · L Mushak Assist ·
Space dodge · E interact · Esc pause.

**Mobile:** virtual joystick bottom-left, action buttons bottom-right, pause always
visible. Mushak: DASH, USE. Vinayaka: HIT, DIVINE, DODGE, MUSHAK. Buttons are re-laid
out whenever the controlled character changes or touch input is first detected. Both
input paths feed the *same* normalised axis — there is no separate mobile movement code.

**Mushak:** move, dash (i-frame-free burst, short cooldown), interact, fit through
`mouseOnly` gaps, trigger mechanisms, collect, assist Vinayaka. Mushak cannot defeat
large enemies — that is what makes switching meaningful.

**Vinayaka:** basic attack (arc), divine attack (radial, costs energy), dodge (short
invulnerability), Mushak Assist (stun/interrupt on cooldown), tusk throw (phase 4 only).

### Tuning (`G.Tune`, `20_entities.js`)

- Mushak: speed 215, dash 560 for 0.16s, dash cd 0.85s, hp 60, radius 13.
- Vinayaka: speed 156, hp 100, energy 100 (regen 9/s), radius 20.
  Attack 11 dmg / 0.34s cd / 74 range / 2.0 rad arc.
  Divine 30 dmg / 32 energy / 136 radius / 1.1s cd.
  Dodge 520 speed / 0.22s / 0.95s cd / 0.34s i-frames.
  Assist: 8s cooldown, 14 dmg, 2.0s stun.
- Small Asura: hp 34, speed 118, dmg 8, 0.55s windup, 100 pts.
- Heavy Asura: hp 92, speed 62, dmg 17, 0.95s windup, 160 pts.
- Gajamukhasura: hp 620, speed 74, 1200 pts.

Every enemy telegraphs: idle → chase → **windup (visible flash + ground mark + sound)**
→ strike → recover. Combat must never reward pure button-mashing.

## 6. Boss: Gajamukhasura

Phase thresholds are fractions of max HP: **0.72 / 0.46 / 0.20**.

1. **Strength** — charges and ground slams. Teaches spacing.
2. **Pressure** — adds shockwave rings and energy volleys; a second delayed ring follows
   the slam.
3. **Cooperation** — the boss holds a shield that reduces damage to **0.18×** unless he
   has been stunned by a Mushak Assist. This is the phase that proves Mushak is
   essential: avoid → assist → open → strike → repeat.
4. **The Final Moment** — the tusk throw unlocks. Only a tusk that lands while
   `coreOpen > 0` ends the fight. A missed tusk **returns to his hand** ("The tusk
   returns to his hand") so the phase can never soft-lock.

Losing shows **JOURNEY INTERRUPTED** with *Retry battle* / *Exit to menu*. Retry restarts
the boss encounter only, never the whole game (−250 score per retry).

Hostiles (enemies, hazards, boss) are frozen while a dialogue box is open or during a
character-switch flourish, so the player is never hit while unable to act.

## 7. Scoring

```
base      = modaks×50 + flowers×30 + durva×20 + divine items×90
          + enemy points + assist points (40 each)
          − damage taken×6 − retries×250            (clamped at 0)
timeBonus = max(0, (22 − minutes) × 120)
noHit     = 1500 if zero damage taken
total     = base + timeBonus + noHit
```

Stars: **3** at ≥9000, **2** at ≥6000, otherwise **1**.

Replay archetypes the numbers are tuned to support: Explorer (collect everything),
Speedrunner (time bonus), Combat Master / Perfect Run (the no-hit bonus and damage
penalty), Collector (optional pickups off the main path).

Saved locally under `localStorage['mushak_vinayaka_save_v1']`:
`{ best, bestStars, introWatched, runs, settings:{ music, sfx, shake, lowFx, skipIntro } }`.

## 8. Opening cinematic

Path `assets/video/opening.mp4`, 8–15 s, supplied externally (Gemini-generated); the
build inlines it as a base64 data URI so the page is self-contained. Replacing the file
and re-running the build is the only step needed to swap it — no game logic touches it.

Fallback chain, per §47 of the prompt: try to play → if autoplay is rejected, show
**"Play the opening film"** → if the video errors, show **"Continue to the game"**. Skip
button always present; Esc / Space / Enter also skip. Once watched, `introWatched` lets
the player skip automatically. Menu music stays silent until the film is done, and no
audio starts before a user gesture.

## 9. Presentation

- Palette: marigold `#F2A81D`, gold-light `#FFD97A`, kumkum `#D6432F`, sandal `#F3E3C3`,
  leaf `#2F7D5B`, indigo night `#1A1033` / `#0D081C`.
- Type: "Yatra One" (display) + "Mukta" (UI), Google Fonts, with fallbacks.
- Environment themes: divine, forest, ruins, cavern, asura, arena — each with its own
  ground tiling, prop set and lighting, per the prompt's visual hierarchy.
- Score currency is called **punya**.
- Particles: pooled, hard cap 420 live. Reduced-effects setting halves emission.
- Logical resolution 960×540, DPR-scaled and letterboxed; portrait shows a rotate hint
  but remains playable. Landscape is the preferred orientation.

## 10. Refinement pass (visuals, logo, controls)

A second pass polished presentation without touching story, chapter structure,
scoring, or the boss fight logic described above.

- **Logo.** The user-supplied circular emblem (`assets/img/logo.png`, 1254\u00b2) is
  used as-is, aspect-ratio preserved, scaled down to two embedded sizes
  (`logo_420.png`, `logo_160.png`) so it doesn't bloat the page. It appears on
  the loading screen, after the opening film (logo reveal beat), and on the
  main menu, drawn via `G.Assets.drawLogo()` in `00_core.js`. If a build ever
  ships without a logo file, the menu falls back to the original text title
  automatically \u2014 nothing crashes.
- **Loading screen / opening / logo reveal.** `#loading` (DOM overlay) shows
  briefly while fonts load. During the opening film, `#introTip` rotates four
  short gameplay tips in a small semi-transparent lower-third pill, never
  covering the video. When the film plays to completion, `#reveal` fades the
  logo in for ~1.8s before the menu; an explicit Skip/Esc bypasses the reveal
  and goes straight to the menu, per "the player can skip."
- **Visible controls.** `G.UI.keycap()` draws a proper keyboard keycap chip;
  `G.UI.showControlHint()` shows a small auto-fading strip ("MOVE / ATTACK /
  DIVINE / DODGE / MUSHAK ASSIST") the first time each character becomes
  playable, in keycaps on desktop or icon glyphs on touch. The full "How to
  Play" screen now uses the same keycaps and opens automatically on a
  player's very first run (dismissed with a "GOT IT" button), saving
  `tutorialSeen` to localStorage; it's reachable again from Settings anytime.
- **Rebindable controls.** `attack`, `divine`, `dodge`, `assist`, `interact`
  and `pause` can be remapped from Settings \u2192 Customize Controls
  (`G.Input.rebind`/`resetBindings` in `00_core.js`). Conflicts are detected
  and shown ("KEY ALREADY ASSIGNED \u2026") without committing the change; Esc
  cancels a pending rebind. Bindings persist in the same save blob under
  `keymap`. Movement (WASD + arrows) stays fixed and is not part of the
  rebindable set \u2014 a deliberate scope line, noted here rather than hidden.
- **Mobile HUD.** Touch buttons now show an icon + label, a radial gradient
  fill, and a genuine cooldown sweep ring (rather than a flat darken) plus a
  soft ready-pulse.
- **Character switch banner.** Replaced the old full-screen flash with a
  small sliding pill at the top of the screen naming the new character.
- **Environment depth.** Every level now gets a soft directional light wash,
  a light vignette (heavier in the dark realms), and low-rate themed ambient
  particles (drifting motes/embers/leaves); the divine theme adds faint god
  rays. Vinayaka and the boss got gradient shading on their main body shapes
  for a less flat look.
- **Honest scope note.** This is still procedural canvas art, not
  illustrated/painted assets \u2014 see \u00a72 for why, and the final chat report
  for what "visual overhaul" concretely means here versus what would need
  real art assets to go further.

## 11. Non-goals

Do not turn this into a platformer, RPG, card game, quiz, endless runner or multiplayer
game. Do not add a character-select menu. Do not add long exposition — dialogue stays
short and skippable. Do not add third-party assets that would complicate contest
licensing.
